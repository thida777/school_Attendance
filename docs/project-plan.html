Final-year thesis · project plan · Plan v2.0

Student Attendance Analytics System ប្រព័ន្ធវិភាគវត្តមានសិស្ស

A Laravel web system and a Java Android app that let a Cambodian high school take attendance in about one minute per class, and find the students who need help before it is too late.

Laravel + MySQL Android (Java) 2 login roles + parent messages English + Khmer Solo student project

01Problem and goal

Many high schools in Cambodia still record attendance on paper. It is slow, easy to lose, and nobody sees the patterns: which students miss school often, which days are worst, and which classes have a problem. By the time someone notices, a student may already be close to dropping out.

Objectives

  • Let teachers record attendance on a phone in under one minute for a class of 40 to 50 students.
  • Give the school office a dashboard with attendance rates, trends and comparisons.
  • Flag at-risk students automatically with 4 risk levels (Critical, High, Medium, Low) and early-warning alerts.
  • Tell parents quickly: an absence alert and a monthly report by Telegram (or SMS), in Khmer and English.
  • Export reports to PDF and Excel.

02Build approach

Web first

Laravel holds the database, the admin pages and the API. The Android app only sends and reads data through that API, so it cannot work until the web side exists.

Static first, then dynamic

Every page is built as plain HTML with fake data first, so the design can be fixed while change is cheap. Then each page moves into Laravel Blade and the fake data is replaced with real data. The Android app follows the same idea with static XML screens first.

Permission rules (agreed)

  • A teacher sees only their own classes and subjects, and edits attendance on the same day only. Past days are corrected by the admin.
  • Teachers can use both the Android app and the web.
  • A homeroom teacher also sees their whole homeroom class, in all subjects, with its at-risk students.
  • An absent student can have an optional reason: not given, sick, family matter, school activity, other.
  • Only Admin and Teacher log in. Students and parents have no accounts (decided: Plan A). Student and parent accounts are future work.
  • Parents receive Telegram messages if they joined the school's bot, otherwise SMS. Every message is logged.
  • Every change to saved attendance is written to an audit log (Corrections page). The Insights page finds patterns automatically. Interventions record follow-up actions for at-risk students.

The take attendance screen is the most important screen in the system. Because everyone starts as Present, the teacher only taps the few students who are absent, then reviews and submits.

05Features

Core

  • Login for Admin and Teacher on web and app
  • Manage students, classes, subjects, teachers, parent contacts, assignments and the timetable
  • Import students from Excel
  • Take attendance; edit on the same day
  • History per student and per class

Analytics

  • Cards: total students, today's rate, absent today, at-risk count
  • Monthly and weekly trend
  • Absences by day of week and by subject
  • Class comparison
  • Risk levels, early-warning alerts, follow-ups, parent messages, PDF / Excel export

Rate = (present + late) ÷ all records. No timetable module: the teacher picks class, subject and period directly, which saves about a day of work.

Design decisions

  • Modern glass style: see-through blurred panels over a soft colour wash, floating sidebar and top bar, large round corners.
  • Soft teal as the main colour, chosen to be easy on the eyes and different from the green used for Present.
  • No pure white page and no pure black text; status colours toned down.
  • Light mode, and a dark mode in dark navy blue instead of black.
  • Plus Jakarta Sans for English, Kantumruy Pro for Khmer.
  • English / Khmer switch and light / dark switch on every page.

09Testing and defense day

  • One command builds a full demo school: 6 classes, about 250 students, 2 months of attendance, one admin and six teacher logins, a weekly timetable and a parent contact for every student.
  • Automated tests for login, saving attendance, role permissions and analytics numbers.
  • App tested on the emulator first, then on a real phone on the same Wi-Fi.
  • Demo story: teacher saves attendance on the phone → admin dashboard changes → student appears in the at-risk list → parent receives a Telegram alert → report is exported.
  • Backups: a screen recording of the demo and a database copy on a USB drive.
