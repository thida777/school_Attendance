Users, the school structure, students and their parents

Plan v2.0 rules built into the database: only Admin and Teacher log in · parents are contacts that receive Telegram or SMS messages · attendance is only Present or Absent, with an optional absence reason.

Only school staff have accounts. The role decides which screens a user can open.

4. Data dictionary: attendance, analytics and parent contact

Lessons, records, the audit log, follow-ups, parent messages and early warnings
Page 4 of 7 · Student Attendance Analytics System
attendance_sessions
ColumnTypeDescription
idbigintPrimary key
school_class_idbigintFK → school_classes.id
subject_idbigintFK → subjects.id
teacher_idbigintFK → users.id (who recorded it)
datedateDay of the lesson
periodtinyintLesson period, 1 to 8

One lesson where attendance was taken. Unique: (school_class_id, date, period), so the same lesson cannot be recorded twice.

attendance_records
ColumnTypeDescription
idbigintPrimary key
attendance_session_idbigintFK → attendance_sessions.id
student_idbigintFK → students.id
statusenumpresent or absent, nothing else
absence_reasonenumOptional: not_given, sick, family_matter, school_activity, other
notevarcharOptional

One row per student per lesson. Unique: (attendance_session_id, student_id). All analytics come from this table. Rate = present ÷ all records.

attendance_corrections
ColumnTypeDescription
idbigintPrimary key
attendance_record_idbigintFK → attendance_records.id
changed_bybigintFK → users.id (who made the change)
old_statusenumpresent or absent, before
new_statusenumpresent or absent, after
reasonvarcharWhy it was changed
created_attimestampWhen the change was made

Audit log. Teachers correct on the same day; the admin corrects past days. Records are never changed silently.

interventions
ColumnTypeDescription
idbigintPrimary key
student_idbigintFK → students.id
created_bybigintFK → users.id
actionvarchare.g. Parent message (Telegram), meeting with parent
notestextOptional
action_datedateWhen the action was taken
follow_up_datedateWhen to check again
rate_before / rate_afterdecimalAttendance rate before, and when closed
statusenumopen or closed
closed_attimestampWhen it was closed

Follow-up actions for at-risk students. rate_before and rate_after show whether the action helped.

parent_messages
ColumnTypeDescription
idbigintPrimary key
guardian_idbigintFK → guardians.id
student_idbigintFK → students.id
sent_bybigintFK → users.id; empty = sent by the system
typeenumabsence_alert or monthly_report
channelenumtelegram or sms
bodytextMessage text, Khmer then English
statusenumpending, sent, failed
errorvarcharWhy sending failed
sent_attimestampWhen it was delivered

Every message to a parent, so the school can prove what was sent and when.

alerts
ColumnTypeDescription
idbigintPrimary key
teacher_idbigintFK → users.id (who should see it)
typeenumabsent_streak, risk_up, not_recorded
student_idbigintFK → students.id, for student alerts
timetable_slot_idbigintFK → timetable_slots.id, for "not recorded"
datedateDay of the alert
messagevarchare.g. Absent 3 school days in a row
handled_attimestampWhen the teacher handled it
handled_bybigintFK → users.id

Early warnings. Risk levels themselves are calculated, not stored: Critical (<70% or 5+ days in a row), High (70–79%, 3–4 days or down 10+ points), Medium (80–89% or down 5–9), Low.
